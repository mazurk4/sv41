# 第17・18回: インフラ構成の提案書(課題⑥・評価課題)

お客さんのサイトが、アクセスの多いときに落ちてしまいます。**他社の提案書をもっと良くした、自分の提案書** を作ってください。1人で進めます。

> お客さん・他社・価格は、すべて **架空** です。クラウドの契約や支払いは **必要ありません**(申し込まないでください)。

## フォルダ構成

```
17_infra_proposal/
├── 01_hearing.md            ← お客さんの話(困りごと・今の構成・数字)
├── 02_other_proposal.md     ← 他社(X社)の提案書
├── 03_price_list.md         ← 部品と価格の表(この値段で計算する)
├── 04_proposal_template.md  ← 提案書のフォーマット
├── 04_proposal_template.docx ← 同じもの(Word)
├── example_yamaneko.md      ← 見本(授業で説明した、別の会社の提案書)
└── images/                  ← アクセスと負荷のグラフ(ニュースの日・SNS の夜)
```

## 進め方

| 回 | やること |
| --- | --- |
| 第17回 | 提案の作り方を聞く → `01`・`02` とグラフを読んで、**問題点を書き出す** |
| 第18回 | 提案書を作る → **Teams に提出** |

1. `01_hearing.md` とグラフを読む。**何が、いつ、なぜ** 詰まっているか?
2. `02_other_proposal.md` を読む。**良い所** と **足りない所** は?
3. `03_price_list.md` から部品を選んで、構成を決める
4. `04_proposal_template` に書く。1〜7 は必ず書く

## 提出

- **Teams の課題⑥** に提出(期限は Teams を見る)
- **形式は自由**: Word・PowerPoint・Google ドキュメント・Markdown・PDF など。手書きの構成図を写真で貼ってもよい
- フォーマットの **項目** がそろっていれば、見た目は変えてよい

## 評価

正解は1つではありません。「安さを優先」でも「止まらないことを優先」でも、**理由が通っていれば** 同じように評価します。

| 項目 | 点 | 見るところ |
| --- | --- | --- |
| 1. 現状の問題と原因 | 20 | **グラフや数字を根拠** に、何が詰まっているか書けている |
| 2. 他社案の評価 | 15 | **良い所と足りない所** の両方を書けている |
| 3. 構成図と、選んだ理由 | 25 | A・B それぞれの特徴に合っている。**なぜその構成か** が分かる |
| 4. 監視と運用 | 15 | **何を見て、いくつで、だれに** 知らせるかが具体的 |
| 5. 費用 | 10 | 価格表で計算できている。今・他社案と比べている |
| 6. 移行と、戻し方 | 10 | 順番が分かる。失敗したときの **戻し方** がある |
| 7. 自分の判断 | 5 | 使った資料・AI と、**自分で決めたこと・直したこと** が書けている |
| **合計** | **100** | |

**追加点**(できた人だけ。合わせて最大 +25。合計の上限は100点)

| 追加点 | 点 | 見るところ |
| --- | --- | --- |
| ⭐ 提案書としてまとまっている | 最大 +5 | お客さんにそのまま出せる(読みやすい・図や表が見やすい・専門用語に説明がある) |
| ⭐ 調べて、具体的に提案している | 最大 +10 | 実際のサービス名・料金・制限などを調べ、**出典(URL と見た日)** を書いている |
| ⭐ プログラムの更新も提案している | 最大 +10 | PHP 7.4 から新しい版への更新を、**版を選んだ理由・進め方・リスク** まで書いている |

## AI を使ってよい?

**使ってかまいません**。ただし、

- AI の答えを **そのまま出さない**。お客さんの数字・グラフと合っているか、自分で確かめる
- 「7. 自分の判断」に、**AI に頼んだこと** と、**AI の答えから直した所とその理由** を書く(使わなかった人は「使っていない」と、自分で迷って決めた所を書く)
- 料金やバージョンは古いことがある → **公式のページ** で確かめる
