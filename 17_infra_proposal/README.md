# 第17・18回: はじめての提案書(サイトの作り方と置き場所の提案・課題⑥・評価課題)

お客さんの2つのサイトが、同じ1台のサーバーで動いていて、一緒に止まってしまいます。**他社(X社)の提案書をもっと良くした、自分の提案書** を作ってください。1人で進めます。

> お客さん・他社・価格は、すべて **架空** です。クラウドの契約や支払いは **必要ありません**(申し込まないでください)。

## フォルダ構成

```
17_infra_proposal/
├── 01_hearing.pdf            ← お客さんの基本情報(困りごと・今の構成・エンジニアのメモ・希望)
├── 02_other_proposal.pdf     ← 他社(X社)の提案書
├── 03_price_list.pdf         ← 部品と価格の表(この値段で計算する)
├── 04_proposal_template.docx ← 提案書のフォーマット(Word。Google ドキュメントでも開ける)
├── 05_how_to_ask.pdf         ← ヒアリングのしかた(Teams での質問)
├── 06_how_to_write.pdf       ← 提案書の作り方ガイド(はじめての人は、まず1〜3)
├── 07_cost_sheet.csv         ← 費用の計算シート(Excel・Google スプレッドシートで開く)
├── example_short.pdf         ← 見本①(授業で説明した、別の会社の提案書。分量の目安)
├── example_yamaneko.pdf      ← 見本②(同じ会社。書き方の脚注つき。★追加点まで入れた例)
└── images/                   ← 白い構成図(提案書に貼ってよい)
```

## 進め方

| 回 | やること |
| --- | --- |
| 第17回 | 提案書の作り方を聞く → `01`・`02` を読んで、**問題点を書き出す** → 質問を考える |
| 第17回のあと〜提出の期限 | **Teams で質問する**(ヒアリング)。1回目は **第18回まで** がおすすめ |
| 第18回 | 作り方と置き場所の考え方を聞く → 提案書を作る |
| 第18回の翌週の授業の開始まで | **Teams に提出** |

作る順番(くわしくは `06_how_to_write.pdf`)

1. `01_hearing.pdf` を読む。**何に困っていて、なぜそうなるか** → 項目1
2. `02_other_proposal.pdf` を読む。**良い所** と **足りない所** は? → 項目2
3. 足りないことを **Teams で質問する**(`05_how_to_ask.pdf`) → 項目7
4. A と B の置き場所、A の作り方(フレームワーク)、B の作り直し(Docker・PHP と MySQL の版)を決める → 項目3
5. 運用と費用を決める → 項目4・5
6. 移し方と戻し方を決める → 項目6
7. 自分の判断とまとめを書く → 項目8・0(できれば ★9)

> 授業の中で終わらなくてかまいません。家での作業の目安は **3〜4時間**。まずは `06` の「**最低ライン**」まで。

## 提出

- **Teams の課題⑥** に提出。期限は **第18回の翌週の授業の開始まで**(日付は Teams の課題を見る)
- **形式は自由**: Word・PowerPoint・Google ドキュメント・Markdown・PDF など。手書きの構成図を写真で貼ってもよい。ファイルでもリンクでもよい
- フォーマットの **項目** がそろっていれば、見た目は変えてよい。分量の目安は **A4 で3〜5枚**

## 評価

正解は1つではありません。「安さを優先」でも「止まらないことを優先」でも、**理由が通っていれば** 同じように評価します。

| 項目 | 点 | 見るところ |
| --- | --- | --- |
| 1. 現状の問題と原因 | 10 | 資料を根拠に、**なぜ困るのか** まで書けている |
| 2. X社の案の評価 | 10 | **良い所と足りない所** の両方を書けている |
| 3-1. 分け方と構成図 | 10 | A と B が **一緒に止まらない**。図で分かる |
| 3-2. A: コーポレートサイトの作り方 | 15 | フレームワークを **くらべて** 選んでいる。**広報がどうやって更新するか** まで書けている |
| 3-3. B: EC サイトの作り直し | 15 | どこで・どう動かすか(**本番も Docker** だと○)。PHP と MySQL の **版と理由**、進め方 |
| 4. 運用 | 10 | 止まったとき **自分たちで戻せる**(管理画面から再起動できる、など)。バックアップ・更新のしかた |
| 5. 費用 | 5 | 価格表で計算できている。今・X社の案と比べている |
| 6. 移行と、戻し方 | 10 | A と B の順番。**データ** をどうするか、失敗したときの **戻し方** |
| 7. ヒアリングで分かったこと | 10 | 質問して分かったことを、**提案に反映** している |
| 8. 自分の判断 | 5 | 使った資料・AI と、**自分で決めたこと・直したこと** が書けている |
| **合計** | **100** | |

**追加点**(できた人だけ。合わせて最大 +25。合計の上限は100点)

| 追加点 | 点 | 見るところ |
| --- | --- | --- |
| ★ 提案書としてまとまっている | 最大 +5 | お客さんにそのまま出せる(読みやすい・図や表が見やすい・専門用語に説明がある) |
| ★ 調べて、具体的に提案している | 最大 +10 | 実際のサービス名・料金・制限などを調べ、**出典(URL と見た日)** を書いている |
| ★ 監視に触れている | 最大 +5 | 止まったことに **どうやって気づくか**(何を見て、だれに知らせるか) |
| ★ 本番の Docker の設定の案がある | 最大 +5 | `compose.yaml` などの案 |

> **監視は、書かなくても減点しません**。

## AI を使ってよい?

**使ってかまいません**。ただし、

- AI の答えを **そのまま出さない**。お客さんの条件(エンジニア1人・広報が更新する・予算・期限)と合っているか、自分で確かめる
- 「8. 自分の判断」に、**AI に頼んだこと** と、**AI の答えから直した所とその理由** を書く(使わなかった人は「使っていない」と、自分で迷って決めた所を書く)
- 料金やバージョンは古いことがある → **公式のページ** で確かめる
