# 第17・18回: はじめての提案書(サーバー構成の提案・課題⑥・評価課題)

お客さんのサイトが、アクセスの多いときに落ちてしまいます。**他社(X社)の提案書をもっと良くした、自分の提案書** を作ってください。1人で進めます。

> お客さん・他社・価格は、すべて **架空** です。クラウドの契約や支払いは **必要ありません**(申し込まないでください)。

## フォルダ構成

```
17_infra_proposal/
├── 01_hearing.pdf            ← お客さんの基本情報(困りごと・今の構成・数字・グラフ)
├── 02_other_proposal.pdf     ← 他社(X社)の提案書
├── 03_price_list.pdf         ← 部品と価格の表(この値段で計算する)
├── 04_proposal_template.docx ← 提案書のフォーマット(Word。Google ドキュメントでも開ける)
├── 05_how_to_ask.pdf         ← ヒアリングのしかた(Teams での質問)
├── 06_how_to_write.pdf       ← 提案書の作り方ガイド(はじめての人は、まずこれ)
├── 07_cost_sheet.csv         ← 費用の計算シート(Excel・Google スプレッドシートで開く)
├── example_short.pdf         ← 見本①(授業で説明した、別の会社の提案書。分量の目安)
├── example_yamaneko.pdf      ← 見本②(同じ会社。書き方の脚注つき。⭐追加点まで入れた例)
└── images/                   ← グラフと白い構成図(提案書に貼ってよい)
```

## 進め方

| 回 | やること |
| --- | --- |
| 第17回 | 提案書の作り方を聞く → `01`・`02` とグラフを読んで、**問題点を書き出す** → 質問を考える |
| 第17回のあと〜提出の期限 | **Teams で質問する**(ヒアリング)。1回目は **第18回まで** がおすすめ |
| 第18回 | 構成の考え方を聞く → 提案書を作る |
| 第18回の翌週の授業の開始まで | **Teams に提出** |

作る順番(くわしくは `06_how_to_write.pdf`)

1. `01_hearing.pdf` とグラフを読む。**何が、いつ、なぜ** 詰まっているか? → 項目1
2. `02_other_proposal.pdf` を読む。**良い所** と **足りない所** は? → 項目2
3. 足りないことを **Teams で質問する**(`05_how_to_ask.pdf`) → 項目7
4. `03_price_list.pdf` から部品を選んで、構成を決める → 項目3・4・5
5. 移し方と戻し方を決める → 項目6
6. 自分の判断とまとめを書く → 項目8・0(できれば ⭐9)

> 授業の中で終わらなくてかまいません。家での作業の目安は **3〜4時間**。まずは `06` の「**最低ライン**」まで。

## 提出

- **Teams の課題⑥** に提出。期限は **第18回の翌週の授業の開始まで**(日付は Teams の課題を見る)
- **形式は自由**: Word・PowerPoint・Google ドキュメント・Markdown・PDF など。手書きの構成図を写真で貼ってもよい
- フォーマットの **項目** がそろっていれば、見た目は変えてよい。分量の目安は **A4 で3〜4枚**

## 評価

正解は1つではありません。「安さを優先」でも「止まらないことを優先」でも、**理由が通っていれば** 同じように評価します。

| 項目 | 点 | 見るところ |
| --- | --- | --- |
| 1. 現状の問題と原因 | 15 | **グラフや数字を根拠** に、何が詰まっているか書けている |
| 2. X社の案の評価 | 10 | **良い所と足りない所** の両方を書けている |
| 3. 構成図と、選んだ理由 | 25 | A・B それぞれの特徴に合っている。**なぜその構成か** が分かる |
| 4. 運用 | 10 | 夜中に落ちたら・バックアップ・更新のしかたが、**だれが・いつ** まで具体的 |
| 5. 費用 | 10 | 価格表で計算できている。今・X社の案と比べている |
| 6. 移行と、戻し方 | 15 | A と B の順番が分かる。**データ** をどうするか、失敗したときの **戻し方** がある |
| 7. ヒアリングで分かったこと | 10 | 質問して分かったことを、**提案に反映** している |
| 8. 自分の判断 | 5 | 使った資料・AI と、**自分で決めたこと・直したこと** が書けている |
| **合計** | **100** | |

> **監視は、今回の課題に入れません**(別の機会に扱います)。書かなくてよく、書いても点は変わりません。止まったことには **気づけるもの** として書きます(夜中でもエンジニアに連絡は来るものとします。`01` の「だれも気づかなかった」を、項目1の問題や、X社の足りない所に数えるのはかまいません)。

**追加点**(できた人だけ。合わせて最大 +25。合計の上限は100点)

| 追加点 | 点 | 見るところ |
| --- | --- | --- |
| ⭐ 提案書としてまとまっている | 最大 +5 | お客さんにそのまま出せる(読みやすい・図や表が見やすい・専門用語に説明がある) |
| ⭐ 調べて、具体的に提案している | 最大 +10 | 実際のサービス名・料金・制限などを調べ、**出典(URL と見た日)** を書いている |
| ⭐ PHP の更新も提案している | 最大 +10 | PHP 7.4 から新しい版への更新を、**版を選んだ理由・進め方・リスク** まで書いている |

## AI を使ってよい?

**使ってかまいません**。ただし、

- AI の答えを **そのまま出さない**。お客さんの数字・グラフと合っているか、自分で確かめる
- 「8. 自分の判断」に、**AI に頼んだこと** と、**AI の答えから直した所とその理由** を書く(使わなかった人は「使っていない」と、自分で迷って決めた所を書く)
- 料金やバージョンは古いことがある → **公式のページ** で確かめる
