# 第10回: 自分の作品をCloudflareにデプロイしてみる

第9回は `cafe-site` を公開しました。今日は **自分の作品** を、手動で公開します。1人で進めます。

## フォルダ構成

```
10_cloudflare_deploy/
└── sample/
    └── portfolio/      ← PHP など、そのまま公開できない作品の人の紹介ページ
        ├── index.html
        ├── style.css
        └── images/
```

## 授業の前に

- 配布資料を最新にする(`git pull`)
- Cloudflare にログインできることを確かめる
- 自分の作品のフォルダが、どこにあるか確かめる

## ハンズオン① 自分の作品を公開する

まず、公開用のフォルダを用意します。

| 作品 | 公開するフォルダ |
| --- | --- |
| HTML / CSS / JavaScript | 新しいフォルダに、必要なファイルだけをコピーする |
| Vite / React / TypeScript | 下のコマンドでビルドしてできた `dist` |
| PHP / Node.js のサーバー / MySQL | `sample/portfolio` をコピーして、紹介ページに書き換える |

Vite などのビルド(作品のフォルダで):

```sh
docker run --rm -v "${PWD}:/app" -w /app node:24-alpine sh -c "npm ci && npm run build"
```

### 公開してはいけないもの

アップロードしたものは、全部 URL で開けると思ってください。

- `.env`、パスワード、API キー
- データベースのファイル、ダンプ(`.sql`)
- 自分のメモ、古いファイル
- 他人の個人情報、許可のない写真
- 使ってよいか分からない画像・音楽・フォント
- `node_modules`、`Dockerfile`、`compose.yaml`(サイトには要らない)

### 公開の手順

1. 公開用のフォルダの中身を確かめる
2. **Workers & Pages** → **Create application** → **Get started**(Pages のほう)
3. **Drag and drop your files** を選ぶ
4. **Project name** を入れる(例: `work-ユーザー名`)
   - 半角の小文字・数字・ハイフンを使う
   - URL の一部になり、あとから変えられない
5. **Deploy site** のあと、公開用のフォルダをドラッグする
6. アップロードが終わったら **Save and Deploy**
7. URL を開いて、画像・リンク・スマホの幅を確かめる
8. URL の最後に `/cdn-cgi/trace` を足して開き、`colo=` を見る
   - この画面には自分の IP アドレスも出るので、ほかの人に見せない

### `portfolio` の使い方

1. `sample/portfolio` を、配布資料の外にコピーする
2. `index.html` の「ここを書き換える」の部分を、自分の内容にする
3. 作品の画面のスクリーンショットを `images/` に入れて、`index.html` の画像の行を有効にする
4. 本名や顔写真を出したくない人は、載せなくてよい

## ハンズオン② 更新して、元に戻す

### 更新

1. 手元のファイルを1か所変える(Vite の人はビルドもやり直す)
2. Cloudflare でプロジェクトを開く
3. **Create a new deployment** を選ぶ
4. **Production** を選び、公開用のフォルダをもう一度ドラッグする
5. **Save and Deploy** のあと、URL を開いて確かめる

### ロールバック

1. プロジェクトの **Deployments** を開く
2. **All deployments** で、1つ前の行の右の「…」を押す
3. **Rollback to this deployment** を選んで、確かめる
4. URL を開いて、元に戻ったことを確かめる

## 課題④

Teams で提出します。

1. 公開した URL(`cafe-site` ではなく、自分の作品または紹介ページ)
2. 公開しなかったファイルを1つと、その理由

料金はかかりません。クレジットカードの登録や、有料プランは不要です。

## つながらないとき

| 症状 | 対処 |
| --- | --- |
| どの URL も同じページが出る | `404.html` がないときの Pages の動き。ファイルの場所と名前を確かめる |
| 画像・CSS が出ない | 大文字・小文字とパスを確かめる |
| 真っ白になる(Vite) | `dist` を上げているか確かめる |
| ファイルが多すぎて上げられない | `node_modules` が入っている。画面からは 1,000個まで |
| トップページが開かない | `index.html` がフォルダの一番上にあるか確かめる |
| URL が開かない | 1分ほど待つ。URL が合っているか確かめる |
| 画面の表示が手順と違う | 画面が変わっていることがある。公式の案内を見る: https://developers.cloudflare.com/pages/get-started/direct-upload/ |

## 片付け

公開したサイトは、第11回が終わるまで消さないでください。

ここで作ったプロジェクトは、あとから GitHub につなげません。第11回は新しいプロジェクトを作ります。

パスワードなどを公開してしまったときは、すぐに講師に伝えて、そのパスワードを変えてください。プロジェクトを消しても、誰かが保存しているかもしれません。
